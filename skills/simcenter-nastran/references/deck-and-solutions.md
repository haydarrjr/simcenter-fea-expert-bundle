# Deck and solution checks

- Treat Executive Control (`SOL`), Case Control (global defaults overridden by each `SUBCASE`) and Bulk Data separately. Resolve every `INCLUDE` relative to its containing deck inside an authorized root. Preserve the dependency closure, including hashes, when staging. Treat conditional/unsupported syntax and unexplained active controls as unresolved.
- Small fixed fields are eight characters; large fields have an eight-character card/continuation ID and four sixteen-character data fields. Columns beyond 72 carry continuation metadata in fixed format. Preserve blank fields and the continuation relationship; free format uses comma-delimited fields. Compact exponents such as `2.0694+8` are not ordinary Python floats. A translator can attach trailing data to `ENDDATA`.
- `GRID CP` positions a node; `CD` sets displacement/output directions; `PS` sets permanent constraints. Compare all three when matching an archive. Compare actual coordinate definitions, not ID equality; scoped non-basic frames need audited transforms. Resolve element → property → material, including density, temperature-dependent tables and their activation. A `MATT1` table does not itself apply a temperature field.
- **SOL 101:** Identify effective `LOAD`, `SPC` and `MPC` selectors. Resolve multipliers and nested set references, including `SPCADD`/`MPCADD`; verify local frames, constrained DOFs and prescribed values. Do not infer DOF equivalence from matching SPC labels. Compute load and reaction wrenches about the same point in the same frame and units. For proportional loading from zero, compare `u^T f` with twice the linear ramp work only if prescribed motions and thermal contributions are accounted for. Distinguish centroid, corner and averaged stress data. With an unverified live frame or unresolved deck differences, retain archive status or use a newly qualified non-overwriting static export.
- **SOL 103:** Check the effective `METHOD` resolves to the intended `EIGRL`. With both bounds blank and `ND` populated, Lanczos targets the lowest `ND` roots ([Siemens Lanczos reference](https://docs.sw.siemens.com/en-US/doc/PL20251024315444291.basic_dynamics/html/id472276?audience=external), 2606). For a free-free part, exclude active external SPC/MPC paths, permanent constraints, preload, and artificial grounding; do not remove verified internal connectivity. Confirm mass definitions and requested real nodal eigenvectors. Preserve signed eigenvalues from F06; a magnitude-like cycle column does not convert a negative root to a physical oscillation frequency.

## Text helper

Run the [read-only helper](../scripts/deck.py) on the exact exported or staged deck:

```powershell
python skills\simcenter-nastran\scripts\deck.py .work\job\main.dat --root .work\job
python skills\simcenter-nastran\scripts\deck.py .work\job\main.dat --root .work\job --expect-closure .work\closure.json --free-free --nd 26
```

- Without `--root`, only the named deck is authorized; any INCLUDE is unresolved. With `--root`, use literal, single-line quoted relative paths. INCLUDEs are fragments within a section, resolved from the containing file; section delimiters and card continuations cannot cross file boundaries. Absolute paths, aliases through symlinks/junctions, missing files, cycles, variables and escapes are unresolved. Read from a stable, task-owned directory; the report describes the bytes read, not later changes on disk.
- JSON `files` records the size and SHA-256 of every file read; `includes` records source file/line and target. `--expect-closure` takes an exact `{ "relative/path.dat": "<sha256>" }` map using paths relative to `--root` (or the deck's directory). Use it to compare a staged closure with a previously recorded closure; extra, missing or different files are unresolved. Keep reports and any `--cards` output with the authorized evidence.
- The parser requires `SOL`, `CEND`, `BEGIN BULK`, and `ENDDATA`. It accepts the observed eight-hex-digit `ENDDATA` suffix as opaque translator metadata, not as a verified checksum. It reads UTF-8 text with ASCII active records (apart from INCLUDE filenames), bounded to 64 MiB per file, 128 MiB expanded and 32 nested INCLUDEs. Supported Bulk Data layouts are small/large fixed and comma-delimited free fields, with matching continuation labels or anonymous continuation records in the same layout. Interior blanks are preserved; trailing blanks can be omitted. Unsupported control, conditional syntax, malformed continuations and active records after `ENDDATA` make the inspection unresolved.
- By default, `TEXT_INVENTORIED` reports `sol`, global and effective per-subcase controls, and card counts (use `--cards` for raw field strings and source lines). A null subcase ID denotes the implicit case. Bulk cards are inventoried, not interpreted in this mode: in SOL 101, resolve referenced sets and verify their effects separately.
- Use `--observe` with the same authorized root for advanced records such as `SDAMPING`, `RANDOM` options, qualified `METHOD`, continued `SET`, and executive `ASSIGN`. It records raw field locations, the apparent Case Control subcase, possible continuations and lexical Bulk Data heads. It resolves only the explicitly authorized literal INCLUDE closure. ASSIGN targets remain unresolved. `RECORDS_OBSERVED` always carries `effective_sets: UNVERIFIED` and cannot be combined with `--free-free` or used to admit a solver job.
- `--free-free` checks a narrow standalone SOL 103 structural continuum solid profile. Each effective subcase needs `METHOD` bound to `EIGRL` with blank `V1`/`V2`, positive `ND` (or the exact requested `--nd`), and real `DISPLACEMENT = ALL`. Only basic `GRID CP`/`CD` and blank `GRID PS` are supported. Any explicit constraint, load, preload or thermal selector and any card or parameter outside the profile is rejected. Unselected conventional SPC/MPC or load set definitions are not evidence of active grounding. Explicitly enabled `AUTOSPC` is outside the profile; default solver elimination still needs review. `MATT1` and `TABLEM1` definitions alone do not activate temperature loading.
- Exit `0` means inventory completed or `free_free.status` is `PROFILE_MATCH`; exit `1` means `REJECTED` by that profile; exit `2` means inspection is `UNRESOLVED` or arguments are invalid. **A profile match is not engineering acceptance or launch authorization.** Connectivity (including a single connected body), material/property bindings, density, units, geometry, runtime overrides and solved modes remain manual checks. Investigate rejection rather than modifying the export to pass. The helper does not interpret binary results, infer coordinate equivalence or replace the Siemens solver.

Expected diagnostic evidence: exact job path/ID, `END OF JOB`, terminal successful solver log, no unresolved fatal, and nonempty matching result output. Check geometry flags and singularity eliminations independently of completion. On rigid modes, distinguish unused continuum rotations from unintended translation restraint with a DOF listing or shape evidence; a count alone is not proof.
