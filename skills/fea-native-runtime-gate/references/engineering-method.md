# Admit and verify an official Siemens operation

Identify the product release, the actual MCP namespace and tool schema, live backend identity, work/display parts, stable object labels, owner, revision, dirty state, and source path of the intended work copy. For a derived conclusion require independent evidence for the full specific quantity. For a bolted joint, object counts cannot identify step-specific member regions, coordinates or bolt/contact state.

Use the current global model readers for original evidence and independent readback. Reject a response whose part fingerprint, region scope or expected state conflicts with the request. When pagination is absent, keep a truncated read PARTIAL. A session health response proves connectivity only.

Treat capabilities separately for edit, persistent save, reopen, deck export, solve, job monitoring and result export. A documented NXOpen method, return code, sandbox proof and approved journal source are separate observations. Use the controller's existing operation, dispatch and native-observation records. Generic live journal scope excludes save, solve and submit. Use a separately advertised, qualified path for those effects. Do not chain a solver job to a save whose effect is unknown.

Capture baselines and independent observations. For a persisted setup, reopen or obtain an equally authoritative saved-state read and check ownership, targets, settings and dependencies. For a solver job, reconcile job identifier, effective deck, logs, result files and the saved revision. On timeout preserve the operation receipt and reconcile state before retry. For readback that changes a result selection, use a task-owned context and verify restoration.
