# Native persistence on Designcenter 2612

The Windows 2612.1700 standalone workflow saves owned PRT, FEM and SIM files in an isolated native NXOpen process using `NXBIN\run_journal.exe`. Live Designcenter Open MCP can reopen and inspect saved files. The live Python sandbox blocks `Save` and `SaveAs`; when updating an active model, use an admitted service or an operator save. A batch session has its own loaded state and cannot save in-memory changes from the interactive session.

1. Use a fresh approved directory and unique part base names across PRT, FEM and SIM, including the idealized PRT when used. Verify batch mode and intended file ownership. Save CAD and FEM dependencies before saving the SIM. For Python 2612.1700 use `BasePart.SaveComponents.FalseValue` and `BasePart.CloseAfterSave.FalseValue` for an individual part save. Check `NumberUnsavedParts` and `NumberUnsavedObjects` and dispose the save status.
2. Record file hashes. In a new process with no loaded parts, open the CAD and then close its tree. Reopen the SIM from disk. Verify load status, ownership, CAD and FEM links, expected geometry and mesh, solution state and dirty flags. Recompute hashes. A saved file alone cannot confirm unloaded dependencies or changed state.
3. If live proof is requested, capture the current work/display parts and dirty state. Open the saved task-owned part through the qualified Designcenter Open session, independently read the CAE state and mesh through their appropriate profiles, then restore and verify the original roles. Close only the owned test tree. Resolve any ambiguous call by independent observation before dispatching a dependent effect.

To persist a derived standalone SIM under a new name, use `BasePart.SaveAs(absolute_target)` from `run_journal.exe` on the owned batch part. Confirm the target does not exist and part dependencies are correctly saved and scoped. Check and dispose the returned save status, then open the new target independently to verify its dependency chain, added objects, dirty flags and file identity. Save As of a SIM can retain the existing FEM dependency. Create and validate separate dependencies explicitly when isolation requires them.
