# Traceable offline FEA report

Use a clear title identifying the model and study. Put outcome, evidence status and critical findings on the first page. Cover provenance, model, FE definition, mesh quality, relevant solution setups/results, integrated interpretation, verification, conclusions and appendix. Honor the requested output format; use printable HTML only as the default. Keep machine detail in a separate evidence folder.

- Discover BatchPost, open the exact saved result path, then list real loadcases, iterations, result and component names, units and export options. Prefer high-resolution PNG or SVG only if the current connector supports it. Choose meaningful views for load path and critical regions. Verify original image pixels, content, legend and the selected field before publication. Preserve the original images and avoid CSS distortion, smoothing values or reusing a view under a different name.
- For every figure identify the exact solution/subcase or mode, state and field, unit, frame when known, recovery/averaging, deformation scaling and viewpoint. Use precise labels. If a setting is unavailable, say so in its caption. Separate deformation display scale from physical displacement and modal normalization.
- Use export data and solver evidence for numerical tables. Preserve location identity, signed component, units, source and rounding. Show the force/moment or energy evidence with quantitative residuals when available. Do not transcribe visual legend ticks as exact extrema. A missing reaction, stress allowable or modal frequency leaves the affected conclusion open.
- Write an evidence manifest with input paths, SHA-256, states, tool requests/responses or scoped evidence paths, and links from findings to figures or quantities. Keep original evidence, derived calculations and interpretations attributable. Report archives separately where live revision matching cannot be proven.
- Open links programmatically, verify nonempty image/data assets and source labels, and inspect representative exported figures at readable size. Use genuine figures only. Exclude blank stress/mode panels where data are unavailable and state the exact blocker in that section. Ensure local assets, navigation and print layout do not depend on network resources or the IDE.
- For a standalone PDF, generate to a staging path and reopen with an independent local reader. Check searchable required text, embedded figures, numbered pages/captions, and bounding boxes against page margins; render every page and inspect tables, legends, symbols and breaks at readable size. Text extraction alone cannot prove absence of overlap or clipping. Fix failures before promoting to the requested filename; retain the exact PDF hash and verification results outside the article.
- If PyMuPDF is already available, the optional [PDF preflight](../scripts/check_pdf.py) checks search terms, on-page glyph/image bounds and image placements. It does not replace rendered visual review, margin policy, figure-state validation or a check for overlapping content.
